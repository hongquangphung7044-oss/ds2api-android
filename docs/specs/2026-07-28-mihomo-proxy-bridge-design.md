# mihomo 代理桥接设计 (方案 A)

- 日期: 2026-07-28
- 作者: hongquangphung7044-oss
- 状态: **已实现**（v4.6.1-mihomo-vision-fix1）
- 上游基准: ds2api v4.6.1 + main（含视觉路由）

## 目标

为 ds2api-android 增加机场订阅导入能力，让不同 DeepSeek 账号定向选择出口节点，节点失败时顺位切换到备用节点。

## 非目标

- 不修改上游 ds2api 的 Go 源码（避免同步冲突）
- 不实现自定义协议解析（依赖 mihomo 内核）
- 不做负载均衡（只做主备 fallback）

## 核心约束

- App 架构是「Go 二进制交叉编译为 .so，子进程 exec」——所有代理协议支持必须编译进二进制
- 上游 ds2api 只支持 SOCKS5（`golang.org/x/net/proxy`）
- 用户订阅是混合协议（ss/vmess/trojan/hysteria 等），参考 mihomo 能力
- DeepSeek 请求统一访问 `chat.deepseek.com`，无法按目标域名区分流量

## 方案选择

**方案 A: 集成 mihomo 作为本地 SOCKS5 桥（已选）**

mihomo 作为第二个子进程运行，解析订阅、暴露本地 SOCKS5 端口，ds2api 账号代理指向本地端口。节点选择/故障转移由 mihomo 的 selector/fallback group 处理。

对比方案 B（Go 内嵌协议库）和方案 C（仅 SOCKS5）的理由见 brainstorming 记录。方案 A 协议支持最全、故障转移成熟、ds2api 改动最小。

## 架构

### 双子进程

```
[DS2API Android App (Java)]
  ├─ ServerService (前台 Service, 协调启动)
  │   ├─ 子进程1: libmihomo.so
  │   │   - 解析机场订阅 (proxy-providers)
  │   │   - 多入站 SOCKS5 端口隔离 (listeners, 7890/7891/...)
  │   │   - RESTful API :9090
  │   │   - fallback group 自动健康检查
  │   └─ 子进程2: libds2api.so
  │       - HTTP API :5001
  │       - 账号 ProxyID 指向本地 mihomo SOCKS5 端口
  └─ ProxyConfigActivity (原生 UI, 节点绑定)
```

### 多端口隔离（关键设计）

问题：多个账号共享一个 SOCKS5 端口时，无法区分哪个账号走哪个出口节点。

解法：每个账号独占一个 SOCKS5 入站端口，每个端口绑定一个独立的 fallback proxy-group。mihomo `listeners` 配置多入站：

```yaml
listeners:
  - name: inbound-acc-0
    type: socks
    port: 7890
    proxy: acc-<hash-0>
  - name: inbound-acc-1
    type: socks
    port: 7891
    proxy: acc-<hash-1>
```

账号 A 流量 → 7890 → acc-group-A → 选定节点
账号 B 流量 → 7891 → acc-group-B → 选定节点

物理隔离，零竞争。

### ds2api 零改动

App 启动 mihomo 后，自动往 ds2api 的 config.json 注入 SOCKS5 代理条目并设置 Account.ProxyID：

```
账号 A → mihomo 端口 7890 → Proxy{ID:"mihomo-0", Type:"socks5", Host:"127.0.0.1", Port:7890}
                           → Account.ProxyID = "mihomo-0"
```

ds2api 的 Go 代码完全不改——它本来就支持 SOCKS5 代理和 Account.ProxyID 绑定。所有新逻辑在 App 层完成。

### 启动顺序

1. ServerService 启动
2. 释放 libmihomo.so 到可执行目录
3. 读取 config.json 的 mihomo 段，生成 mihomo config.yaml
4. 启动 mihomo 子进程，探测 :9090 就绪（30s 超时）
5. 为每个账号注入 Proxy 条目 + 设置 Account.ProxyID，写回 config.json
6. 启动 ds2api 子进程（照旧）
7. 两个进程日志合并显示（前缀 [mihomo] / [ds2api] 区分）

## 配置结构

### config.json 新增 mihomo 段

与上游 proxies/accounts 并列，上游会忽略未知字段：

```json
{
  "mihomo": {
    "enabled": true,
    "subscription_url": "https://airport.example.com/sub",
    "subscription_update_interval": 3600,
    "api_port": 9090,
    "api_secret": "<auto-generated-uuid>",
    "socks5_base_port": 7890,
    "account_bindings": [
      {
        "account_identifier": "xxx@gmail.com",
        "node_names": ["香港-01", "日本-01", "美国-01"],
        "current_node_index": 0
      }
    ]
  }
}
```

字段说明：
- `node_names`: 用户在 UI 手动选定的节点名列表，顺序即优先级（第一个主节点，后续顺位备用）
- `current_node_index`: 当前使用的节点索引，故障转移时递增
- `socks5_base_port`: 起始端口，第 N 个账号用 base_port + N

### mihomo config.yaml 生成规则

```yaml
mixed-port: 7890
allow-lan: false
mode: rule
log-level: info
external-controller: 127.0.0.1:9090
secret: "<api_secret>"

proxy-providers:
  airport:
    type: http
    url: "<subscription_url>"
    interval: <subscription_update_interval>
    path: ./providers/airport.yaml
    health-check:
      enable: true
      url: https://chat.deepseek.com/
      interval: 300

proxy-groups:
  - name: acc-<hash-0>
    type: fallback
    use: [airport]
    filter: "^(香港-01|日本-01|美国-01)$"
    url: https://chat.deepseek.com/
    interval: 300
  - name: acc-<hash-1>
    type: fallback
    use: [airport]
    filter: "^(日本-01|香港-02)$"
    url: https://chat.deepseek.com/
    interval: 300

listeners:
  - name: inbound-acc-0
    type: socks
    port: 7890
    proxy: acc-<hash-0>
  - name: inbound-acc-1
    type: socks
    port: 7891
    proxy: acc-<hash-1>
```

filter 用正则匹配用户选定的节点名，fallback group 只包含选定节点。

注意：使用 `listeners` 模式时，每个入站端口的流量直接绑定到指定 proxy-group，`rules` 段不参与路由决策（listeners 优先级高于 rules）。因此配置中不需要 rules 段，避免歧义。

## 故障转移（两级）

### 第一级：mihomo fallback group 自动转移
- 每个 group 类型为 fallback，内置健康检查（url: https://chat.deepseek.com/, interval: 300s）
- 主节点（node_names[0]）健康检查失败 → 自动切到 node_names[1]
- 主节点恢复 → 自动切回

### 第二级：ds2api 请求失败时 App 主动切换
- App 监听 ds2api 日志，出现 account_muted 或连接超时 → 调用 mihomo API PUT /proxies/<groupName> {"name":"<下一个节点>"}
- current_node_index 递增，持久化到 config.json
- 下次启动从新索引开始

## 订阅更新

- 自动：mihomo proxy-providers 原生支持 interval 自动更新
- 手动：WebUI/App 点"更新订阅" → App 调 mihomo API PUT /providers/airport 强制刷新
- 节点列表获取：App 调 mihomo API GET /providers/airport 返回节点列表给 UI 展示

## mihomo 二进制获取

### 来源

mihomo 官方 Release 的 mihomo-linux-arm64-vX.Y.Z.gz。纯 Go 构建（CGO_ENABLED=0 GOOS=linux GOARCH=arm64），Android 上可直接运行（Linux 内核 + 不依赖 glibc）。

### 新增 scripts/build-mihomo.sh

```bash
#!/usr/bin/env bash
set -euo pipefail
MIHOMO_VERSION="${1:-v1.18.10}"
ROOT="$(cd "$(dirname "$0")/.." && pwd)"
OUT_DIR="$ROOT/app/src/main/jniLibs/arm64-v8a"
TMP="$(mktemp -d)"

URL="https://github.com/MetaCubeX/mihomo/releases/download/${MIHOMO_VERSION}/mihomo-linux-arm64-${MIHOMO_VERSION}.gz"
curl -L -o "$TMP/mihomo.gz" "$URL"
gunzip "$TMP/mihomo.gz"
mkdir -p "$OUT_DIR"
cp "$TMP/mihomo" "$OUT_DIR/libmihomo.so"
chmod 0755 "$OUT_DIR/libmihomo.so"
rm -rf "$TMP"
```

版本锁定在脚本里，避免 breaking change。build-go.sh 不变。

## 实现记录（与原设计的差异）

本设计已实现于 v4.6.1-mihomo-vision-fix1。实现过程中对原设计做了以下调整：

### 1. 配置存储独立化
原设计将 mihomo 配置放在 `config.json` 的 `mihomo` 段。实际实现改为独立文件 `mihomo_config.json`，原因：ds2api Go 服务端会写回 `config.json`，嵌套的 mihomo 段会被覆盖丢失。config.yaml 生成时从独立文件读取。

### 2. provider 类型改为 file（借鉴 FlClash）
原设计用 `type: http` 让 mihomo 内核直接拉订阅。实际改为 `type: file`，由 App 层（`downloadSubscription`）下载订阅文件。原因：很多机场对 mihomo/clash 默认 UA 返回 403，App 层下载可自由控制 UA/重试/超时，绕过拦截。

### 3. group 类型改为 select + 手动切换
原设计用 `type: fallback` + filter 正则做自动故障转移。实际改为 `type: select`，由 App 层通过 API `PUT /proxies/{group}` 手动切换节点。原因：fallback 的 filter 正则对含特殊字符（emoji/中文）的节点名匹配不可靠，且用户希望明确控制使用哪个节点。故障转移改为：主节点切换失败时，App 顺位尝试 node_names 中的下一个。

### 4. provider 名用索引而非哈希
原设计 group 名为 `acc-<hash-N>`。实际用 `acc-{index}`、provider 名用 `sub-{index}`，简单稳定，避免哈希计算和特殊字符问题。

### 5. 时序修复（关键 bug 修复）
原设计第 7 步"探测 :9090 就绪"仅检查 `/version` API 可用。但此时 mihomo 的 proxy-provider 仍在异步加载订阅文件，group 引用的 provider 节点尚未就绪 → `PUT /proxies/{group}` 返回 404。

修复（v4.6.1-mihomo-vision-fix1）：`applyNodeSelection` 先轮询 `fetchNodeList` 等待 provider 节点加载完成（最长 15s），再执行切换；`switchNode` 失败时重试 3 次（间隔 800ms）。`verifyProxyExit` 同样增加 3 次重试（间隔 1.5s），应对 SOCKS5 端口刚监听或 group 节点切换中的短暂 ECONNREFUSED。

### 6. 视觉路由（上游功能，非本设计）
上游 ds2api main 分支（commit 24abb927）新增视觉路由：含图片请求自动路由到 vision 模型，响应模型名回写为原模型。本 App 通过 Rebuild Native workflow 同步上游二进制即可获得此能力，无需 App 层改动。用户在 WebUI 设置中开启即可。
